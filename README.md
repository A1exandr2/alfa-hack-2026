# credit

Умный кредитный кабинет предпринимателя — проект для Альфа Хак.

- `frontend/` — интерфейс, зона Frontend.
- `backend/` — API и бизнес-логика, зона Backend.
- `ml/` — обучение, эксперименты и скоринг, зона ML.
- `devops/` — Docker, CI/CD и развертывание, зона DevOps.
- `docs/` — общая документация: каждый описывает запуск и использование своей части.
- `data/` — общие синтетические данные.

Внутри своей папки каждый сам выбирает структуру. Чужие части меняем по согласованию.

## Как работаем

Модульный монолит: Backend разделён на логические модули, Frontend работает через его API. Бизнес-правила и окончательные решения принадлежат Backend. Подключение AI/ML-сервиса и его runtime-интеграция — зона DevOps; ML-фасад импортируется внутрь Backend, а генерация объяснений выполняется отдельным Ollama runtime.

Каждый делает задачи в своей ветке от `main`, затем открывает PR в `main`. Документацию обновляем вместе с кодом. Ветка `dev` объединяет `backend` и `ml`; исходные ветки сохранены. Общий запуск находится в корневом `docker-compose.yml` и Makefile.

## Что уже сделано

- Локальный запуск через Docker Compose: PostgreSQL, миграции Alembic, FastAPI и Nginx; команды сборки, проверки и тестов — через Makefile.
- Авторизация: регистрация пользователя, login, JWT, `GET /api/v1/auth/me`; пароли хешируются.
- Компания: привязка по ИНН через `CompanyProvider`, просмотр данных компании. Сейчас используется синтетический Demo Provider.
- Финансы: получение через `FinancialProvider`, частичное обновление показателей пользователем. Данные помечаются `DEMO` или `USER_VERIFIED`.
- Кредитная история: агрегированный просмотр через `CreditHistoryProvider`; пока только синтетический demo provider, реальные данные БКИ не подключены.
- Каталог: список и карточка кредитного продукта. Все условия синтетические и помечены `DEMO`.
- Скоринг и рекомендации: `POST /api/v1/company/score` использует данные компании из БД, ML-фасад и Qwen 3.5 4B через Ollama; при ошибке модели возвращает `Fallback_Rules`.
- Тесты Backend запускаются командой `make test` на отдельной временной PostgreSQL.

## Что ещё не реализовано

Frontend, создание и обработка заявок, статусы и аудит, кредитные решения и предложения, персональные новости. В Backend бизнес-правила остаются отдельным слоем; ML возвращает демонстрационную рекомендацию, а не оформляет кредитное решение.

## Быстрый запуск

Требуются Docker Engine с Compose v2+ (`--wait`), GNU Make и Python 3 на хосте.

```bash
make up-gpu  # NVIDIA GPU + NVIDIA Container Toolkit; без GPU: make up
make check
make check-ml
make status
```

`make up` (CPU) или `make up-gpu` (NVIDIA) создаёт локальный `.env` со случайными паролем PostgreSQL и JWT-ключом, собирает backend и запускает PostgreSQL, миграции Alembic, API, Nginx и Ollama, затем скачивает `qwen3.5:4b` в постоянный Docker volume. Первая загрузка занимает время и несколько ГБ диска; последующие запуски используют сохранённую модель. Для запуска без Ollama: `make up-core`. Существующий `.env` сохраняется; секреты не хранятся в `.env.example` и Git.

- Swagger: http://localhost:8080/docs
- API: http://localhost:8080/api/v1
- Проверка базы: http://localhost:8080/api/v1/ready

```bash
make logs SERVICE=backend
make test
make down
```

`make down` сохраняет базу и модель в Docker volumes. `make test` использует отдельную временную БД. `make check` проверяет полный auth-сценарий через Nginx и создаёт одного уникального demo-пользователя. Все команды: `make help`.

Параметры портов и локальные настройки — в `.env`. При занятом `8080` измените `APP_PORT`, при занятом `55432` — `POSTGRES_PORT`, затем выполните `make up`.
