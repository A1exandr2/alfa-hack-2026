# Панель сотрудников

Адрес: `http://localhost:8080/#/admin`. Вход выполняется через обычную форму кабинета. Аккаунты ADMIN и REVIEWER после входа переходят в панель. Клиент не видит пункт «Управление»; сервер проверяет права на каждом запросе.

## Полномочия

- USER: свой кабинет, без доступа к административному API.
- REVIEWER: общая очередь заявок, поиск по компании/ИНН/номеру, фильтр статуса, история, первоначальная оценка и последние 20 сохранённых версий данных. Ручное рассмотрение только заявок MANUAL_REVIEW.
- ADMIN: всё перечисленное, сводка по пользователям/компаниям/статусам заявок, поиск пользователей, назначение USER/REVIEWER, блокировка/разблокировка, журнал действий сотрудников.

Изменение доступа требует причины. Решение через панель требует обоснования и второго подтверждения. Исходная оценка модели и снимок данных не перезаписываются. В базе решение специалиста, событие заявки и запись журнала сохраняются одной транзакцией. Повтор идентичного запроса не дублирует запись. На заблокированном аккаунте запрещены вход и запросы по существующим JWT. Права берутся из текущей записи пользователя, а не из роли в токене.

Создавать ADMIN через публичную регистрацию или менять доступ существующих администраторов через панель нельзя. Учётная запись администратора создаётся серверной командой. API не возвращает хеши паролей, ключи провайдеров и токены. Панель не выдаёт деньги, не создаёт договоры и не подменяет проверку достоверности отчётности.

## Первый администратор

После сборки backend и применения миграции 0019 подготовьте вне Git JSON-файл с полями `email`, `password` (20–128 символов), `full_name`; ограничьте права файла до 0600. Передайте файл через stdin:

```sh
docker compose --env-file .env exec -T backend python -m app.admin.bootstrap < .local/admin-credentials.json
```

На сервере доступен `make admin-bootstrap`: он получает ADMIN_EMAIL/ADMIN_PASSWORD из локального .env. Логин Admin является серверным псевдонимом ADMIN_EMAIL; обычные пользователи входят по почте. Команда создаёт новый аккаунт и запись журнала. Если почта занята, существующий аккаунт остаётся без изменений. Пароль хранится в БД только в виде хеша. Локальный файл с выданными данными не коммитится и не попадает в Docker build context.

В первой версии нет редактирования каталога, массовых операций, удаления данных и email-сброса пароля. Это отдельные сценарии, которые требуют собственных ограничений и журнала. Страница использует адаптивную компоновку кабинета; визуальную проверку на реальном устройстве нужно выполнить отдельно.
