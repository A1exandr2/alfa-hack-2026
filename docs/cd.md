# CD: deploy → healthcheck → 10. DAST (Nuclei Scan)

Изменения развёртываются отдельным workflow `.github/workflows/cd.yml` после успешного CI для точного commit SHA ветки main. Ветка разработки сама на production не развёртывается. Ручной запуск разрешён только с main и также проверяет успешный CI через GitHub API. Конкурирующие production-конвейеры сериализованы: новая версия не заменит сайт посреди DAST предыдущей версии.

CI включает дополнительные проверки Python/Checkov/Trivy образа на main и в PR в main автоматически. Сканирование полных Git-историй остаётся включённым; реальные утечки в старых коммитах могут блокировать CI даже после ротации. История в этой задаче не переписывалась, ошибки сканеров не подавляются.

## Последовательность

1. Checkout точного проверенного main commit.
2. Запись SHA; повторная проверка успешного CI для этого SHA.
3. Проверка обязательных параметров production и HTTPS origin.
4. Проверка синтаксиса deploy-скриптов.
5. Архив исходников и зашифрованной конфигурации; открытые секреты и private age identity не включаются.
6. Передача через SSH с заранее закреплённым host key. Проверка SOPS на сервере, активация релиза, Compose build/up, миграции, healthchecks и идемпотентный bootstrap Admin. Очистка старых образов.
7. Проверка внешнего HTTPS `/api/v1/ready` с валидацией TLS без переходов на другой сайт.
8. Summary с SHA.
9. Сохранение контрольной суммы релиза.
10. **DAST (Nuclei Scan)** по живому origin проекта, затем сохранение отчёта.

## Что настроить после аренды сервера

Создайте GitHub environment `production` и задайте настройки (переменные можно хранить на уровне repository либо environment):

| Тип | Имя | Значение |
| --- | --- | --- |
| Variable | `ENABLE_CD` | `true` только после готовности сервера |
| Variable | `DEPLOY_HOST` | IP/DNS SSH-сервера |
| Variable | `DEPLOY_USER` | SSH-пользователь |
| Variable | `DEPLOY_PORT` | Порт SSH, по умолчанию 22 |
| Variable | `PRODUCTION_URL` | Ваш HTTPS origin, например `https://credit.example.org`, без пути |
| Secret | `DEPLOY_SSH_KEY` | Приватный deploy SSH-ключ с доступом только к своему серверу |
| Secret | `DEPLOY_KNOWN_HOSTS` | Проверенная запись SSH host key сервера, для нестандартного порта — с `[host]:port` |

Runner использует существующие метки `[self-hosted, Linux, X64, credit]`. Для CI/CD нужны Docker Compose, SSH/SCP и Python 3. Никакой age identity в GitHub Secrets передавать не требуется: она остаётся на сервере. Host key проверяется строго, автоматического доверия результату ssh-keyscan нет. Не используйте непроверенную запись host key из недоверенного канала.

На сервере установите Docker Compose, Python 3, SOPS и age; для GPU дополнительно NVIDIA Container Toolkit. Установите приватную age identity в `/etc/credit/age/keys.txt` отдельно от архива. Получите bootstrap-архив через `make server-package`, распакуйте его во временный каталог и запустите от root:

```sh
python3 /путь/к/распакованному/проекту/devops/scripts/install-server.py
```

Это устанавливает systemd units, включает автозапуск и ежедневную очистку. Служба приложения впервые запускается самим CD после создания current. SSH-пользователь должен быть root либо иметь passwordless sudo для запуска доверенного deploy-скрипта. Такой доступ даёт полномочия развёртывания кода; он не предназначен для PR из недоверенных fork.

Домен/DNS и внешний reverse proxy с HTTPS настройте до включения CD. Приложение по умолчанию слушает localhost:8080. Не включайте `credit-secrets.path` вместе с CD: конвейер применяет релиз целиком и не должен реагировать на частично переданные файлы. Пока `ENABLE_CD` не задан, deployment не выполняется.

## Релизы и откат

Исходники размещаются в `/opt/credit/releases/<sha>`. Ссылка `/opt/credit/current` выбирает активный релиз, `/opt/credit/previous` — предыдущий. Сначала проверяются SOPS/Compose, затем ссылка переключается атомарно и systemd применяет конфигурацию. Backend и миграции используют образ `credit-backend:<sha>`, поэтому предыдущая версия сохраняет собственный образ. При ошибке старта current возвращается назад и предыдущий релиз запускается повторно.

Откат приложения не выполняет downgrade БД. Изменения схемы должны оставаться совместимыми с предыдущим релизом; перед несовместимой миграцией нужна резервная копия и отдельный план восстановления. Передача архива начинает новую БД только на совершенно новом сервере: существующие Docker volumes сохраняются.

Если Nuclei нашёл High/Critical, CD становится красным, отчёт сохраняется. Автоматического отката по результату DAST нет: прежняя версия может иметь ту же уязвимость. Исправление следует провести отдельным проверенным релизом.

## Очистка образов

`cleanup-images.py` выполняется после успешного развёртывания и ежедневно через `credit-image-cleanup.timer`. Удаляются только образы с меткой `io.credit.project=credit` и тегом `credit-backend:<40-символьный SHA>`, старше 24 часов. Сохраняются три последних успешных версии, current/previous и любые образы, на которые ссылаются контейнеры. Без истории deployments.json очистка отказывается что-либо удалять. Глобальный `docker system prune`, удаление volumes и принудительное удаление используемых образов не выполняются.

Проверка плана без удаления:

```sh
python3 /opt/credit/current/devops/scripts/cleanup-images.py
systemctl list-timers credit-image-cleanup.timer
```

## Nuclei и отчёт

Зафиксированы Nuclei v3.11.1 и официальные шаблоны v10.5.1 по commit SHA; SHA-256 архивов проверяется при установке. Обновление выполняется явно через `devops/dast/tools.lock.json`. Проверены **11 052** подписанных HTTP-шаблона после исключения категорий dos/fuzz/bruteforce/headless/code/intrusive. Проверки выполняются с лимитом 15 запросов/с и параллелизмом 4. Междоменные редиректы, unsigned-шаблоны, выполнение code/headless и OAST отключены. Это внешний неаутентифицированный DAST; бизнес-логика и страницы после входа требуют дополнительных сценариев.

Ошибка запуска, таймаут, недоступность сайта до/после сканирования, отсутствие/повреждение отчёта либо загрузка менее 1000 шаблонов блокируют этап. Находки High/Critical также блокируют CD. Остальные уровни сохраняются для разбора. Из отчёта удалены extracted values, HTTP response/cookies и query-токены, чтобы не повторять утечку секретов через Actions artifacts. Артефакты хранятся 14 дней.

Ручной запуск на своём развёрнутом сайте:

```sh
make dast-install
PRODUCTION_URL=https://ваш-домен make dast-scan
```

Официальные источники: [Nuclei flags](https://docs.projectdiscovery.io/opensource/nuclei/running), [GitHub deployments](https://docs.github.com/en/actions/how-tos/deploy/configure-and-manage-deployments/control-deployments).
