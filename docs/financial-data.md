# Источники финансовых данных

`DATA_MODE=real` — режим по умолчанию. Наличие ключа DaData не означает доступ к бухгалтерской отчётности или БКИ. Без доступного источника поля имеют значение `null`. `DATA_MODE=demo` включает синтетические провайдеры только для демонстрации/тестов.

## Бухгалтерская отчётность

`DADATA_API_KEY` используется сервером для `findById/party` (https://dadata.ru/api/find-party/). Поля `finance.revenue`, `finance.expense`, `finance.year`, `employee_count` отображаются без пересчёта. `income` не подменяет выручку, `debt` означает налоговую недоимку и не подменяет кредитный долг. Чистая прибыль из этих полей не выводится.

- `GET /api/v1/company/financials`: сохранённые показатели; при первом запросе — доступные данные провайдера.
- `POST /api/v1/company/financials/refresh`: обновляет внешние показатели, сохраняет ручные значения. Последний внешний оригинал ручного поля сохраняется в `field_sources[field].registry` отдельно от ручного значения.
- `PATCH /api/v1/company/financials`: частичный ручной ввод, включая `report_year`. Источник `USER_INPUT`, никогда не «подтверждено». Неизменённые поля не меняют происхождение.
- `field_sources`: источник, период и время загрузки каждого доступного поля, автор ручного ввода. Общий источник `MIXED` при сочетании данных.

Поля, которых нет у источника/тарифа, остаются неизвестными. Нет автоматического переключения на демо при 401/403/429/ошибке сервиса.

## Кредитная история

DaData не является интеграцией БКИ. Без отдельного подключения используется `UNAVAILABLE`, без вымышленных кредитов и нулевых просрочек. `PATCH /api/v1/company/credit-history` позволяет сохранить пользовательские сведения отдельно помеченными как неподтверждённые.

Подготовлен адаптер **собственного шлюза организации**, не прямая реализация неизвестного API бюро. Для реального бюро потребуется его договор, документация и реализация шлюза. Нельзя вставлять произвольный URL сайта БКИ и ожидать совместимости.

Настройки только backend: `CREDIT_HISTORY_API_URL` (HTTPS), `CREDIT_HISTORY_API_TOKEN`. Оба значения должны быть заданы. Перенаправления запрещены. Шлюз получает POST на настроенный URL:

```json
{"schema_version":1,"inn":"7325115310","consent_id":"uuid","purpose":"credit_application"}
```

Авторизация: `Authorization: Bearer <token>`. Нормализованный ответ (пример контракта, не реальные сведения):

```json
{"inn":"7325115310","as_of":"2026-01-01T00:00:00Z","active_credits":0,"closed_credits":null,"overdue_count":0,"overdue_amount":"0.00"}
```

ИНН должен совпадать, `as_of` обязателен, с часовым поясом и не в будущем. Отсутствующее значение остаётся `null`. В ответах кабинета источник `BKI_GATEWAY` и дата отчёта `as_of`.

- `GET /company/credit-history/connection`: наличие подключения и активного согласия текущего пользователя для текущей компании.
- `POST /company/credit-history/consent`: `{"accepted":true,"text_version":"credit-report-v1"}` — техническое подтверждение действия пользователя, срок 180 дней. Шлюз/организация должны обеспечивать принятые бюро требования к полномочиям представителя и оформлению согласия; эта версия текста сама по себе не является универсальной формой согласия для всех БКИ.
- `DELETE /company/credit-history/consent`: отзыв. Запись сохраняется в аудите, новые запросы блокируются.
- `POST /company/credit-history/refresh`: запрос внешнего отчёта только при активном согласии. Меняет текущую сводку, но не старые снимки заявок. Ручная сводка заменяется текущим отчётом, её исходные значения сохраняются отдельно в `field_sources[field].user_input` и ранее созданных снимках заявок.

У всех маршрутов выше префикс `/api/v1`. Секреты не возвращаются клиенту и не включаются в выгрузки.

## Проверка заявок

Проверяются наличие всех пяти финансовых показателей, положительная выручка, все четыре поля кредитной истории и корректная дата регистрации. Для реальной компании также требуется год отчётности. Нехватка данных приводит в `NEED_MORE_DATA`, без вызова скоринга. `null` сохраняется в JSON снимка как `null`, не строка и не ноль.

Полные ручные сведения могут использоваться при оценке, но положительная оценка переводится в `MANUAL_REVIEW` с требованием подтверждающих документов. Это не автоматическое одобрение. Исторические снимки и решения не пересчитываются при обновлении компании или источников.

Миграция `0017_financial_sources` удаляет старые синтетические текущие показатели (источник `DEMO`), сохраняет ручные данные, решения и снимки заявок. Перед применением сделайте резервную копию. Откат со значениями `null` запрещён, чтобы не подменять их нулями.
